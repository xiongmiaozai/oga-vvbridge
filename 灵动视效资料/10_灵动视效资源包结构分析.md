# 灵动视效（Vibrant Visuals）完整资源包结构分析

> 整理日期：2026-11-15
> 依据：Microsoft Learn 创作者文档、官方资源包结构图、Minecraft Wiki、bedrock-rs 的 deferred_settings 实现，以及本文件夹内 04–07 号资料
> 适用版本：Bedrock 1.21.120 及以上（部分 schema 已演进到 1.26.x）
> ⚠️ 校验状态：已用官方样例包 `bedrock-samples-v1.26.70.23-preview-full.zip` 逐项核对，发现若干细节偏差，详见 `12_官方样例包校验报告.md`。本文主干结论（三层结构、MERS+TGA、1.21.90 按群系优先、fog 引用方式）均获实物印证。

## 一、先建立一个总体认识：这是「两套体系」叠加

一个完整的灵动视效资源包 = **常规基岩版资源包** + **两套新增机制**：

| 层 | 作用 | 载体 | 粒度 |
|---|---|---|---|
| ① 门禁层 | 告诉引擎「本包含 PBR 资产」 | `manifest.json` 的 `capabilities` | 整包 |
| ② 材质层 | 定义**每个纹理**的表面物理属性 | `*.texture_set.json` + MERS/MER/法线/高度贴图 | 单个纹理 |
| ③ 渲染设置层 | 定义**整个场景**的光照、大气、水、雾、色彩 | 9 类 Keyframe JSON + `*.client_biome.json` | 全局 / 按群系 |

很多教程只讲 ② 或只讲 ③，这是最容易混淆的地方：**纹理集决定"物体怎么反光"，设置 JSON 决定"世界怎么打光"**，两者通过 `identifier` 引用链和 `pbr/global.json` 回退值衔接。

## 二、完整目录树

以下为合并官方示意图、Wiki 目录清单与各 settings schema 文档后的**完整结构**。`[VV]` 标记表示该目录仅在带 `pbr` capability 的包中生效。

> ⚠️ 这是「**创作者可用**」的全集，不是原版包的实存目录。官方样例包实测只有 `atmospherics`、`color_grading`、`lighting`、`water`、`fogs`、`biomes` 六处；`cubemaps/`、`shadows/`、`local_lighting/`、`pbr/` 四个目录在原版包中**完全不存在**（引擎走内置默认值），仅在第三方包需要自定义时才创建。见 `12_官方样例包校验报告.md` 第二、六节。

## 三、门禁层：manifest.json

没有这一步，其余所有 PBR 资产都会被引擎忽略。

```json
{
  "format_version": 1,
  "header": {
    "name": "My Vibrant Visuals Pack",
    "description": "PBR material + lighting pack",
    "uuid": "<唯一 UUID>",
    "version": [1, 0, 0],
    "min_engine_version": [1, 21, 120]
  },
  "modules": [
    {
      "type": "resources",
      "uuid": "<另一个唯一 UUID>",
      "version": [1, 0, 0]
    }
  ],
  "capabilities": ["pbr"]
}
```

要点：

- `capabilities: ["pbr"]` 是**跨平台**写法；`"raytraced"` 也能激活灵动视效（RTX 资产是 VV 资产的子集），但会限定在 RTX 设备，官方明确**推荐用 `pbr`**。
- `min_engine_version` 必须 ≥ `[1, 21, 120]`，否则 PBR 不渲染。
- `modules[].type` 为 `resources`（资源包），不是 `data`。
- 打包时整个目录压缩为 `.mcpack` / `.zip` 即可导入。

> 依据：`06_灵动视效资源包.md:17-35`

## 四、材质层：texture_set.json 与贴图

### 4.1 文件位置与命名

- 每个纹理配一个 `*.texture_set.json`，**与贴图放在同一个子目录**（如 `textures/blocks/`）。
- 贴图后缀约定：基色无后缀、`_mers`、`_mer`、`_normal`、`_heightmap`（Wiki 也记作 `_height`）。
- 格式优先级：**`.tga` > `.png` > `.jpg` > `.jpeg`**（同名时取 TGA）。
- **MERS 必须用 TGA**：Alpha 通道的次表面散射值在 0 和 255 都有意义，Photoshop 等工具优化 PNG 时会丢掉 Alpha=0 区域的 RGB 数据。

> 依据：`05_TextureSet规范.md:168-172`、`02_MERS材质标准.md` 的提示框

### 4.2 schema

```json
{
  "format_version": "1.21.30",
  "minecraft:texture_set": {
    "color": "cactus_side",
    "metalness_emissive_roughness_subsurface": "cactus_side_mers",
    "normal": "cactus_side_normal"
  }
}
```

| 层 | 通道 | 可否用数值/HEX 代替贴图 | 约束 |
|---|---|---|---|
| `color` | RGBA | 可（4 值数组 / HEX） | **唯一必需层**；也是旧管线唯一读取的层 |
| `metalness_emissive_roughness` (MER) | RGB | 可（3 值） | 与 MERS **互斥**；RTX 用这个 |
| `metalness_emissive_roughness_subsurface` (MERS) | RGBA | 可（4 值） | 与 MER **互斥**；仅 VV 支持，`format_version` ≥ `1.21.30` |
| `normal` | RGB | 否 | 与 `heightmap` **互斥** |
| `heightmap` | 单通道 | 可（单值） | 与 `normal` **互斥**；**不能用于物品类纹理** |

数值写法示例：`"metalness_emissive_roughness": "#FBA34C"`、`"color": [180, 140, 190, 255]`。

### 4.3 会导致 `CONTENT_ERROR` 的写法

1. 缺 `color` 层；
2. 同时定义 `normal` 与 `heightmap`；
3. 同时定义 MER 与 MERS；
4. 对物品纹理使用 `heightmap`；
5. 引用的贴图不在**同一个资源包**内，或无法解析；
6. 通道数不符（MERS 贴图必须 4 通道；heightmap 必须单通道）；
7. **用 uniform 值做 MERS 的纹理变体不受支持** —— 要做变体必须提供图片型 MERS 文件。

### 4.4 资源栈行为

同一纹理资源的 texture_set **不合并**，高优先级包的整份定义覆盖低优先级包；且定义只能引用**本包内**的贴图（更高优先级包里的同名贴图不会顶替引用）。

> 依据：`05_TextureSet规范.md:13-172`

## 五、渲染设置层：9 类配置 JSON

### 5.1 目录 / 默认文件名 / schema 对照

| 目录 | 保留的全局默认文件 | 根 schema 对象 | 控制内容 | schema 演进版本（文档记录） |
|---|---|---|---|---|
| `atmospherics/` | `atmospherics.json` | `minecraft:atmosphere_settings` | 瑞利/米氏散射、地平线混合、天空色 | 1.26.20 |
| `color_grading/` | `color_grading.json` | `minecraft:color_grading_settings` | 阴影/中间调/高光、色调映射 | 1.21.90 |
| `cubemaps/` | `cubemap.json` | `minecraft:cubemap_settings` | 天空盒与 IBL 反射源 | 1.21.130 |
| `lighting/` | `global.json` | `minecraft:lighting_settings` | 日月定向光、环境光、天空光、自发光、末地闪光 | 1.26.0 |
| `water/` | `water.json` | `minecraft:water_settings` | 反射、焦散、水波、水下吸收与粒子 | 1.21.40+ |
| `fogs/` | `default_fog_setting.json` | 迷雾定义 | 迷雾 | — |
| `shadows/` | `global.json` | `minecraft:shadow_settings` | 阴影风格、纹素尺寸 | — |
| `local_lighting/` | `local_lighting.json` | `minecraft:local_light_settings` | 指定方块的点光颜色与类型 | 1.21.120 |
| `pbr/` | `global.json` | `minecraft:pbr_fallback_settings` | 无 texture_set 时的 MERS 默认值 | 1.21.40 |

> `cubemaps` / `fogs` / `shadows` / `local_lighting` / `pbr` 属于「整包只有一份」的文件；其余五类支持多实例 + 按群系分配。这一划分来自 bedrock-rs 的 `DeferredSettings` 八类分组。

> ⚠️ **上表末列≠游戏版本，也≠必须写的值**。官方样例包（1.26.70.23-preview）实测各文件 `format_version` 为：atmospherics `1.21.40`、color_grading `1.21.90`、lighting `1.21.70`、water `1.21.120`、fogs `1.21.90`（根 `minecraft:fog_settings`）、client_biome `1.21.120`、texture_set `1.21.30`。`format_version` 指的是**该 schema 被引入或最后修改的版本**，schema 没变就不用升，哪怕游戏已经是 1.26.70。详见 `12_官方样例包校验报告.md` 第四节。

### 5.2 通用文件骨架

```json
{
  "format_version": "1.21.40",
  "minecraft:lighting_settings": {
    "description": {
      "identifier": "my_pack:default_lighting"
    },
    "directional_lights": { ... },
    "emissive": { "desaturation": 0.1 },
    "ambient": { "illuminance": 0.02, "color": "#ffffffff" }
  }
}
```

`format_version` 自 **1.21.40 起必须是字符串**（原为整数数组）；`description.identifier` 必须**带命名空间**，是跨文件引用的唯一键。同类目录下每个文件要有**唯一文件名 + 唯一 identifier**。

### 5.3 关键帧语法（VV 设置文件的核心）

任何标注 `optkeyframe` 的字段，既可以写单值，也可以写成 `{"时间点": 值}` 的对象，引擎按游戏内时间**线性插值**：

```json
"illuminance": {
  "0.0": 100000.0,   // 正午
  "0.25": 20000.0,   // 日落
  "0.35": 400.0,
  "0.5": 1.0,        // 午夜
  "0.65": 400.0,
  "0.75": 20000.0,   // 日出
  "1.0": 100000.0    // 次日正午
}
```

- 键范围 `0.0`（正午）→ `1.0`（下一个正午，24 小时）；
- 目前只支持 **float 与颜色（RGB 数组 / HEX）**，只支持**线性插值**；
- 1.26.0 起 `sky` 与 `ambient` 也支持关键帧。

### 5.4 三份单实例文件示例

```json
// local_lighting/local_lighting.json  (1.21.120)
{
  "format_version": "1.21.120",
  "minecraft:local_light_settings": {
    "minecraft:torch": {
      "light_color": "#EFE39D",
      "light_type": "point_light"
    }
  }
}
```

```json
// pbr/global.json  (1.21.40)
{
  "format_version": "1.21.40",
  "minecraft:pbr_fallback_settings": {
    "blocks":    { "global_metalness_emissive_roughness_subsurface": [0, 0, 255, 0] },
    "actors":    { "global_metalness_emissive_roughness_subsurface": [0, 0, 255, 0] },
    "particles": { "global_metalness_emissive_roughness_subsurface": [0, 0, 255, 0] },
    "items":     { "global_metalness_emissive_roughness_subsurface": [0, 0, 255, 0] }
  }
}
```

> 注：`[0, 0, 255, 0]` 表示非金属、不发光、**完全粗糙**、无次表面散射 —— 这是常见的保守回退值。缺失贴图时的默认值由这里决定，而不是自动取原版纹理。

## 六、引用链：设置如何作用到具体群系

这是 1.21.90 之后**最容易踩坑**的部分。

```
设置文件 (description.identifier: "my_pack:end_lighting")
        ↓ 被引用
biomes/the_end.client_biome.json 的 components
        ↓ 组件
minecraft:lighting_identifier → "my_pack:end_lighting"
        ↓
末地群系生效
```

对应的 5 个 VV 专属组件（cubemap 需 1.21.130+）：

| 组件 | 指向的目录 |
|---|---|
| `minecraft:atmosphere_identifier` | `atmospherics/` |
| `minecraft:color_grading_identifier` | `color_grading/` |
| `minecraft:lighting_identifier` | `lighting/` |
| `minecraft:water_identifier` | `water/` |
| `minecraft:cubemap_identifier` | `cubemaps/` |

> 雾不在这一组：它走通用组件 `minecraft:fog_appearance` 的 `fog_identifier` 字段指向 `fogs/`。
> 本文表格原曾列 `minecraft:fog_identifier` 为第 6 个组件，属笔误，已在 `11_文件与文件夹命名全表.md` 第四节更正。

```json
// biomes/the_end.client_biome.json
{
  "format_version": "1.21.70",
  "minecraft:client_biome": {
    "description": { "identifier": "the_end" },
    "components": {
      "minecraft:atmosphere_identifier":   { "atmosphere_identifier":   "my_pack:end_atmospherics" },
      "minecraft:color_grading_identifier": { "color_grading_identifier": "my_pack:end_color_grading" },
      "minecraft:lighting_identifier":     { "lighting_identifier":     "my_pack:end_lighting" }
    }
  }
}
```

**三条关键规则：**

1. **保留文件名 = 全局默认值**。`atmospherics/atmospherics.json`、`color_grading/color_grading.json`、`lighting/global.json`、`water/water.json` 里的 identifier 会被自动分配给所有群系，除非某个 `client_biome.json` 显式改掉。
2. **1.21.90 起，原版 Vanilla 包内置了按群系配置，且优先级高于全局文件** —— 也就是说，`lighting/global.json` **不再能覆盖**原版的按群系光照。要改某群系，必须新建该类别的 JSON 并在 `biomes/` 里显式引用。
3. 全局文件仍会对**没有专属配置的自定义群系**生效。

### 群系之间的过渡

| 过渡方式 | 类别 | 说明 |
|---|---|---|
| 按**观察者位置**插值 | atmospherics、color_grading、cubemaps、lighting | 玩家走过群系边界时平滑渐变 |
| 按**几何位置**插值 | water | 站在岸边就能看到远处不同水体的外观差异 |

**不能被混合的参数**（同一包内必须保持一致，否则无法过渡）：色调映射算子、`orbital_offset_degrees`、焦散参数、水波开关布尔值。

> 依据：`07_生物群系自定义.md:20-93`

## 八、完整自检清单（做包 / 做转换器时逐条过）

**结构**
- [ ] `manifest.json` 有 `capabilities: ["pbr"]`，`min_engine_version ≥ [1,21,120]`，`modules[].type = "resources"`
- [ ] 各类 settings JSON 的 `format_version` 是**字符串**且带 `description.identifier`（含命名空间）
- [ ] 同类目录下文件名与 identifier 均不重复
- [ ] 想改某群系的效果 → 建专属 JSON + 在 `biomes/*.client_biome.json` 里用对应组件引用，别只改 `global.json`

**材质**
- [ ] 每个 `*.texture_set.json` 与它引用的贴图**同目录、同包**
- [ ] `color` 层必填；MER/MERS 二选一；normal/heightmap 二选一
- [ ] MERS 贴图 4 通道、用 **TGA**；物品纹理不用 heightmap
- [ ] 贴图后缀：`_mers` / `_mer` / `_normal` / `_heightmap`
- [ ] 同名贴图优先 `.tga`
- [ ] 需要纹理变体时提供图片型 MERS，不用 uniform 值

**语义**
- [ ] 金属度与次表面散射互斥（取较大值，相等时优先次表面散射）
- [ ] 宽松写法的 `pbr/global.json` 回退值不会让缺贴图的对象显得突兀
- [ ] 同一包内色调映射算子、orbital offset、焦散参数、水波开关保持一致

## 九、与「Java 资源包 → VV .mcpack」转换器的关系

资料库里的 `MC_JB2VV_源码_V1.0`（Java 资源包 → 基岩版 Vibrant Visuals，一步生成 `.mcpack`）本质上是自动生成上述 **② 材质层**。转换时的对应关系：

| Java / LabPBR 侧 | 生成的 VV 侧 |
|---|---|
| `assets/<ns>/textures/block/*.png` | `textures/blocks/*.png`（基色） |
| `*_s.png`（R=平滑度, G=F0/金属, B=孔隙率/SSS, A=自发光） | `*_mers.tga`（R=金属度, G=自发光, B=粗糙度, A=SSS）—— **通道语义需要重映射** |
| `*_n.png`（RGB=法线, B=材质 AO, A=高度） | `*_normal.tga`（只取 RGB）+ 可选 `*_heightmap.tga`（取 A） |
| 每个纹理 | 一个 `*.texture_set.json` |
| `pack.mcmeta` | `manifest.json`（加 `pbr` capability） |
| 无 | `textures_list.json`（注册短名） |

注意 LabPBR 的 R 是「感知平滑度」，而 MERS 的 B 是「粗糙度」，两者需要做 `粗糙度 = pow(1 - 感知平滑度, 2)` 的转换，不能简单搬通道；LabPBR 的 A（自发光）在 MERS 里变成了 G。这也是 MineGraph 提供 LabPBR→MERS 转换工具的原因。
