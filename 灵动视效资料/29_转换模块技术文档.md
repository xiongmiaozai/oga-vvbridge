> 讲清每类的输入、输出、公式、调用关系与关键约束。行号以 2026-11-20 版本为准。

## 0. 这个模块是什么、不是什么

转换器整页是一个向导（选包 → 扫描 → 配置 → 转换 → 导出）。**转换模块**特指其中
"把一个 Java(LabPBR) 资源包的纹理变成基岩 VV 资源"的那部分纯变换逻辑，
不包含上传/UI/官方对比/打包下载这些外围环节。

一句话边界：

```
Java 包(已解包的 GROUPS) + 用户选项(opt)
        │  ── 转换模块 ConversionModule ──▶
        ▼
基岩条目(E: {name, data}[]) + 报告统计 ──▶ .mcpack
```

**一条必须记住的红线**：转换模块**从不读取官方参考包的任何像素**。
官方包（`bedrock-samples`）只提供"某个基岩纹理名字+目录是否真实存在"的命名证据，
由独立的「官方参考对比」区在**转换之前**处理；对比采纳的结果会写进 `custom` 映射，
再作为转换模块的输入。两者正交，官方素材永远不会进入成品。

## 1. 模块结构（代码里的落点）

模块不是物理拆出的文件——为了守住"单文件离线、手机直接打开"这条立身之本，
它是在同一个 `<script>` 里用**注释分区 + 命名空间**组织出来的逻辑模块：

| 分区标记 | 子模块 | 关键函数 / 常量 | 行号 |
|---|---|---|---|
| `[转换模块·1]` | 重命名与路径映射 | `mapName` / `isPBRDir` / `scan` / `DIR_REDIRECT` / `BUILTIN_MAP`(493) / `ARMOR_*` / `TGA_BASE` / `OVERLAY_*` | 929–1077 |
| `[转换模块·2]` | 贴图通道换算 | `labpbrToMers` | 831–844 |
| `[转换模块·3]` | 法线重建 | `splitNormal` | 845–851 |
| `[转换模块·4]` | UV 几何重构 | `reuvBed` / `bedLegSolid` | 853–928 |
| `[转换模块·5]` | 格式与编码 | `encodeTGA` / `encodePNGBytes` / `makePNG` / `decodePNG` / `normalizeIcon` | 668–830 |
| `[转换模块·6]` | 辅助变换 + 主流程编排 | `convert`（内联 overlay 合成 / 封面 / 过滤 / texture_set / manifest） | 1676– |

数据流：

```
scan ─▶ [1]mapName ─▶ [2]通道换算 ─▶ [3]法线重建 ─▶ [4]UV重构 ─▶ [5]编码 ─▶ E[]
                                    └──────── [6]辅助(overlay/封面/过滤) ────────┘
```

**对外 API** `ConversionModule`（`第 2095 行`，`Object.freeze` 冻结）：

```js
const ConversionModule = Object.freeze({
  version: '1.0',
  naming:   { mapName, isPBRDir, scan, DIR_REDIRECT, BUILTIN_MAP },
  channels: { labpbrToMers },
  normal:   { splitNormal },
  geometry: { reuvBed, bedLegSolid },
  codec:    { encodeTGA, encodePNGBytes, makePNG, decodePNG, normalizeIcon, placeholderIcon },
  pipeline: { convert }
});
```

> 每一项都是对上方**已定义函数的直接引用**，不是第二份实现；主流程 `convert()` 仍
> 按原样直接调用同名函数。因此封装前后行为 100% 一致（已实测 `sameRef === true`）。

## 2. [转换模块·1] 重命名与路径映射（`mapName`，998–1037 行）

不只是改文件名，而是**五层规则叠加**，输入是 Java 原始纹理路径 `raw` 与用户映射 `custom`，
输出是 `{dir, name, changed, src, (skip)}`。

| 层 | 规则 | 说明 |
|---|---|---|
| 目录沿用 | `block→blocks`、`item→items` | 原 Java 子目录保留；不再把非 item/entity/particle/block 一律塞进 `blocks/`（曾导致盔甲/地图被写到基岩不读的目录，见 20 号文档） |
| 护甲重映射 | `ARMOR_DIRS` / `ARMOR_MAT`(`_BABY`) | Java 1.21.2+ 的 `entity/equipment/*` → `models/armor`；材质名 `chainmail→chain`、`turtle_scute→turtle`；层号后缀 `_1/_2/_baby`；无对应（如 `leather_overlay`）返回 `skip:true` |
| 床特例 | `entity/bed/light_gray → silver` | Java 与基岩 bed 目录相同，只浅灰叫法不同 |
| 改名表 | `BUILTIN_MAP`(493) → `custom` | 内置表由 `mapping/build_map.py` 依官方实物核验生成；`custom` 优先级最高 |
| 目录重定向 | `DIR_REDIRECT` + `custom.dir` | 文件名不变、目标在 `blocks/` 深层子目录（如 `warped_planks/crimson_planks → blocks/huge_fungus`）；`custom` 的 `{name,dir}` 对象格式可同时改名字和输出目录，优先级最高 |

`custom` 值两种写法：

```json
{ "java_a": "bedrock_a" }                                   // 只改名（向后兼容）
{ "java_b": { "name": "bedrock_b", "dir": "blocks/deepslate" } } // 改名 + 改目录（官方位置差异采纳时写入）
```

`src` 字段取值：`none`（直传）/ `builtin` / `custom` / `armor` / `armor-skip`，用于报告归因。
配套 `isPBRDir(dir)`（950 行）放行 `blocks/` 及子目录、`entity/*`、`items`、`particle`、`models/armor`；
`scan()`（1052 行）借助 `isJunkPath()`（1043 行）在入口拦截 macOS `._` 资源叉、`__MACOSX/`、含空格文件名。

## 3. [转换模块·2] 贴图通道换算（`labpbrToMers`，832–822 行）

输入：LabPBR `_s` 图逐像素 RGBA + 选项 `opt`；输出：MERS 四通道 `[R,G,B,A]`（各 0–255）。
逐像素计算（`r,g,b,a` 均为 0–255）：

| 源 `_s` 通道 | 语义 | 目标 MERS | 公式 |
|---|---|---|---|
| R | 平滑度 s | **B 粗糙度** | `round(255 · (1 − s/255)²)` |
| G | 金属度 / F0 | **R 金属度** | 二值 `g≥230 ? 255 : 0`；`f0` 策略 `min(255, g/229·255)`；`none` 策略 `0` |
| A | 自发光 | **G 自发光** | `a===255 ? 0 : round(a·255/254)`（255 是保留值） |
| B | SSS / 孔隙率 | **A 次表面** | `b≥65 ? round((b−65)·255/190) : 0`；`opt.sss=false` 则 0 |

**金属与次表面互斥**：取两者较大值，另一个清零（相等时优先 SSS）。
介电质 F0、孔隙率 0–64、AO、POM 高度等 VV 无对应通道的值，计入报告的 `informationLoss`。

## 4. [转换模块·3] 法线重建（`splitNormal`，846–851 行）

LabPBR `_n` 的 **B 通道被 AO 占用**，不是 Z，必须重算：

```
ng = flipY ? 255−g : g        // OpenGL(Y+) → DirectX(Y−) 只翻 G
x = r/255·2 − 1 ; y = ng/255·2 − 1
z = sqrt(max(0, 1 − x² − y²))
return [r, ng, round((z·0.5+0.5)·255)]
```

`flipY` 默认关——VV 与 LabPBR 法线同向，该开关来自第三方实现的推断、非官方明文，故保留可选。
法线整体默认关闭（官方 VV 包几乎不用）。

## 5. [转换模块·4] UV 几何重构（`bedLegSolid` 870 行 / `reuvBed` 874–928 行）

最特殊的一类，**只针对 512×512 的床基色**，用两个真包（Java `ENRO 0.20.2` ↔ 基岩网易版）
逐像素标定：

- Java 是「主岛 352×354 + 侧岛工字形 96×192」两岛布局；基岩几何体按**单连通岛**采样，直接复制会错位。
- 主岛：上半原位；下半上移 48px 删透明缝；顶部木条重定位。
- 床尾木架：取侧岛一个 96×96 单元**横向平铺两次**（`sy=ty, sx=tx%96`，碎块比例不变、无拉伸），
  形状用基岩镂空规格，透明像素用同行最近不透明填充——木纹不拉伸、无白洞。
- 关键点：基色 / MERS / 法线**三张图共用同一套几何 mask**（调用处 1875、1973、1974 行），
  否则颜色与材质通道会错位。非 512² 的床图原样跳过，避免误伤。
- 实测：底部形状 16 色 IOU 1.0、全图差 2.75。详见 `22_` 号文档。

## 6. [转换模块·5] 格式与编码（668–830 行）

**`encodeTGA(w, h, rgba)`（817 行）**：把 RGBA 写成基岩 VV 要求的 **32-bit BGRA TGA**：

- 头 18 字节：类型 2（未压缩真彩）、宽高、（16/17）= 32bit + 8 alpha bits、左下原点；
- 像素从 `y=h-1` 倒序写到 `y=0`（**翻转行序**，左下原点）；
- 每像素按 **B,G,R,A** 顺序写（`buf[p++]=rgba[i+2]; [i+1]; [i]; [i+3]`）——不能只改后缀。
- 全程非预乘，保住 `alpha=0` 像素里藏的材质数据（PNG 绘图工具会优化掉这些数据，故 MERS 用 TGA）。

**`decodePNG` / `encodePNGBytes` / `makePNG`**：PNG 的解码与生成，封面与基色用。
**`normalizeIcon` / `placeholderIcon`**：任意来源、任意尺寸的封面统一成 128×128 PNG；无封面时用中性占位图。

**TGA 目标白名单 `TGA_BASE`（976 行，约 50 项）**：官方对树叶、草、海草、矮蕨、盔甲部分层等只提供 `.tga`，
而基岩按 `.tga > .png > .jpg` 优先级取图——写成 `.png` 会被官方 `.tga` 静默压制。
因此这些目标强制写 `.tga`（1920–1924 行）。

## 7. [转换模块·6] 辅助变换 + 主流程编排（`convert`，1679 行起）

`convert()` 按 `[1]→[5]` 依次调度各子模块，并内联三类辅助变换：

1. **overlay 烘焙**（1897 行 `OVERLAY_SRC`/`OVERLAY_ONLY`）：Java `grass_block_side_overlay` 在基岩无独立文件，
   转换时把它的 alpha **合成进基色**（实测与网易基岩图差 0.12、纯基色差 13.20），并跳过 overlay 组本身。
2. **封面规整**（1812/1819 行）：`normalizeIcon` / `placeholderIcon` → 128×128 `pack_icon.png`。
3. **输出过滤**：非 PBR 目录（map/ui/font/painting/colorormap）跳过、`._` 资源叉拦截、
   `emitted` 集合去重、非法名跳过、盔甲无对应层跳过。

主循环末尾生成配套文件：`*.texture_set.json`（`format_version 1.21.30`）、
`manifest.json`（带 `capabilities:["pbr"]`）、可选多语言 `texts/` 三件套、`pbr/global.json` 回退值（叠加模式关闭时），
最终 `zipStore` 打成 `.mcpack`。

**关键调用顺序**（行号）：

```
1839 mapName(basePath, opt.map)      → 决定输出 dir/name
1875 reuvBed(基色)                    → 床基色 UV 重排
1897 OVERLAY_SRC 烘焙                 → grass_side 等 overlay 合成
1920 TGA_BASE 判定                    → 基色走 .tga 还是 .png
1959 labpbrToMers(r,g,b,a,opt)        → _s → _mers
1964 splitNormal(...,opt.flipY)       → _n → 法线重建
1973 reuvBed(mers, gm) / 1974 reuvBed(normal, gm) → 床三通道共用 mask
1976/1980 encodeTGA → _mers.tga / _normal.tga
1812/1819 normalizeIcon / placeholderIcon → pack_icon.png
```

## 9. 报告的归因字段（模块可读性相关）

`convert()` 维护一组计数器并写入报告 `REPORT`，与模块各子步骤一一对应：

- `mapping`：`builtinTableSize` / `builtinHits` / `customHits` / `unchanged`
- `informationLoss`：F0、孔隙率、AO 等丢弃像素数
- `bedUV`：`bedReuv` / `bedSkip`（床重排成功 / 非 512² 跳过）
- `hygiene`：`junkSkipped` / `invalidPng` / `dupSkipped` / `skippedNoPBR` / `tgaBase` / `overlayComposited`
- `unchangedNames` / `bedTexturesInReport`：未改名项分类（床图由 UV 重排处理，无需改名）
- `failures`：转换失败项
- `reference`：来源 `builtin` / `uploaded`、版本、texture_set 数、官方确认/位置差异/候选统计

## 10. 维护提示（改模块时别踩的坑）

1. **不要搬移函数或用 IIFE 包裹**：`convert()` 依赖 GROUPS / OUT / REPORT / 主题 / 折叠等大量全局状态，
   搬进闭包会破坏作用域。命名空间 `ConversionModule` 只是同一批函数的引用清单。
2. **三处映射表要同步**：`mapping/name_map.json`、HTML 内联 `BUILTIN_MAP`、`mapping/build_map.py` 的 MANUAL 区；
   改映射用 `build_map.py` 重生成，勿手改内联大字符串。
3. **床三通道必须共用 mask**：改 `reuvBed` 时，基色/MERS/法线都要走同一变换，否则通道错位。
4. **TGA 字节序别动**：BGRA + 翻转行序 + 非预乘，三者缺一基岩就读错（见 13 号文档）。
5. **新增"官方位置差异"映射**用 `{name, dir}` 对象格式，`dir` 相对 `textures/`，`mapName` 已支持。
6. **验证方式**：改完先 `node --check`（抽取 `<script>`），再跑 `verify/run_all.sh` 或用真包 `ENRO 0.20.2`
   端到端转换，确认 `failures=0`、组数不丢、报告字段齐全。

## 11 · 内容级核查修复（2026-11-20 19:xx）

> 触发：用户要求「不靠名字相同、看内容对应对不对」搜索官方包对应贴图。

**方法教训（重要）**：ENRO 是第三方**重绘**材质，与 Mojang 原版贴图像素本就不同
（22 号文档里像素一致的是"网易适配包"，不是本包）。因此：
- 「同名但像素差大」≠ 映射错，多半是重绘风格差异；
- 纯色图（玻璃条、白块）用感知哈希会误匹配到随机 UI 图，不可用像素距离单独判映射；
- 判映射正确性要靠**官方目录语义 + 旧名/别名实物核查**（`reeds`/`hardened_clay`/`quartz_block_lines` 这类基岩旧名）。

**映射表 510 → 515**：补 5 条确定性旧名/语义映射：
`quartz_pillar(_top) → quartz_block_lines(_top)`、`sugar_cane → reeds`、
`terracotta → hardened_clay`、`cherry_leaves → cherry_leaves`（同名入表以触发 tga 输出）。
`TGA_BASE` 补 `reeds`、`cherry_leaves`（官方仅 tga / tga 优先于 png，写 png 会被压制）。

**保守未补**：`melon_slice`/`glistering_melon_slice`——官方只有 `items/melon`、`items/melon_speckled`
