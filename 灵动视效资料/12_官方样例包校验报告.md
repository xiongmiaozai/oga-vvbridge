## 三、材质层实测：MERS + TGA 是唯一答案

| 指标 | 实测值 |
|---|---|
| `*.texture_set.json` | **3,171** 个 |
| `*_mers.tga` | **3,171** 个 |
| `*_mer.*`（MER 三通道） | **0** 个 |
| MERS 贴图格式 | **100% `.tga`**，无 PNG/JPG |
| 使用 `metalness_emissive_roughness_subsurface` 的 texture_set | **3,171 / 3,171（100%）** |
| `texture_set` 的 `format_version` | **全部 `"1.21.30"`** |
| 使用 `normal` 字段 | 4 个 |
| 使用 `heightmap` 字段 | **0** 个 |
| `*_normal.*` 文件 | 27 个（大多数未被 texture_set 引用） |

典型实例 `resource_pack/textures/items/bundle_blue_open.texture_set.json`：

```json
{
    "format_version": "1.21.30",
    "minecraft:texture_set": {
        "color": "bundle_blue_open",
        "metalness_emissive_roughness_subsurface": "bundle_blue_open_mers"
    }
}
```

**三点结论：**

1. 原版在 VV 时代**完全弃用 MER**（RTX 那条三通道路径），一律走 MERS。10/11 号文档里「MER 与 MERS 二选一」在规范上没错，但做 VV 包时实际只有 MERS 一种选择。
2. 3,171 对 3,171 的严格 1:1 说明 **纹理集与 MERS 贴图同名、同目录、成对出现** 是硬性约定，不是惯例。
3. 全 TGA 印证了 MineGraph MERS 标准里那段「Alpha=0 会生效、PNG 会被工具优化丢 RGB」的提示 —— 官方自己就是这么存的。这对你的 LabPBR→MERS 转换器是**直接指令**：输出必须是 `_mers.tga`。

> `textures/` 子目录比 11 号文档列的多：`blocks`(3956)、`entity`(2555)、`items`(2662)、`ui`(2046)、`gui`(193)、`trims`(171)、`particle`(96)、`particles`(6)、`models`(78)、`painting`(66)、`environment`(18)、`map`(16)、`colormap`(8)、`misc`(5)、`persona_thumbnails`(4)。注意 **`particle/` 与 `particles/` 同时存在**。

## 四、format_version 的正确理解（10 号文档最需澄清的一点）

实测各类型文件所用版本：

| 类型 | 根 schema | `format_version` |
|---|---|---|
| atmospherics | `minecraft:atmosphere_settings` | `1.21.40` |
| color_grading | `minecraft:color_grading_settings` | `1.21.90` |
| lighting | `minecraft:lighting_settings` | `1.21.70` |
| water | `minecraft:water_settings` | `1.21.120` |
| fogs | `minecraft:fog_settings` | `1.21.90` |
| client_biome | `minecraft:client_biome` | `1.21.120` |
| texture_set | `minecraft:texture_set` | `1.21.30` |

**关键**：这是 **1.26.70.23 的包**，但 atmospherics 仍在用 `1.21.40` 的 schema。说明 `format_version` 指的是**该 schema 被引入/最后修改的版本**，不是当前游戏版本；只要 schema 没改，就不用升。10 号文档表格里的「最新 schema 版本 1.26.20 / 1.26.0」容易被读成「1.26.x 的包必须写这些版本」，属于误导，已在 10 号文档加注修正。全部为**字符串**，这条判断成立。

## 五、引用链实测（印证上一轮的 fog 修正）

90 个 `*.client_biome.json` 的组件出现次数：

| 组件 | 出现数 | 说明 |
|---|---|---|
| `minecraft:fog_appearance` | **90 / 90** | 雾走 `fog_identifier` 字段，指向 `fogs/` |
| `minecraft:water_appearance` | 90 | 水面色，通用组件 |
| `minecraft:atmosphere_identifier` | 89 | VV |
| `minecraft:color_grading_identifier` | 89 | VV |
| `minecraft:lighting_identifier` | 89 | VV |
| `minecraft:water_identifier` | 88 | VV |
| `minecraft:ambient_sounds` | 89 | 通用 |
| `minecraft:biome_music` | 57 | 通用 |
| `minecraft:cubemap_identifier` | **0** | 官方包未使用（与 `cubemaps/` 缺失一致） |

实例 `resource_pack/biomes/extreme_hills_mutated.client_biome.json`：

```json
{
  "format_version": "1.21.120",
  "minecraft:client_biome": {
    "description": { "identifier": "minecraft:extreme_hills_mutated" },
    "components": {
      "minecraft:fog_appearance": { "fog_identifier": "minecraft:fog_extreme_hills_mutated" },
      "minecraft:water_appearance": { "surface_color": "#0E63AB" },
      "minecraft:atmosphere_identifier":  { "atmosphere_identifier":   "minecraft:default_atmospherics" },
      "minecraft:color_grading_identifier": { "color_grading_identifier": "minecraft:coolish_color_grading" },
      "minecraft:lighting_identifier":     { "lighting_identifier":     "minecraft:default_lighting" },
      "minecraft:water_identifier":        { "water_identifier":        "minecraft:default_water" }
    }
  }
}
```

- 上一轮把 10 号文档里的 `minecraft:fog_identifier` 改成「雾走 `minecraft:fog_appearance` 的 `fog_identifier` 字段」—— **实测完全正确**。
- 90 个按群系配置 + 89 个显式 identifier 引用，强力印证 10 号文档第六节那个「**1.21.90 起原版包加入按群系配置、优先于 `lighting/global.json`**」的关键结论。
- 注意很多群系仍指向 `minecraft:default_lighting` / `minecraft:default_atmospherics`，即**保留默认名 + 按群系覆盖**是官方自己的组织方式。

`biomes_client.json` 开头的注释也印证了 11 号文档的说法：

> *"If the default is overwritten in a resource pack then it will overwrite all biomes unless the resource pack defines the biomes."*

## 七、对「Java 资源包 → VV .mcpack」转换器的直接影响

| 转换器环节 | 官方包给出的定论 |
|---|---|
| 输出贴图格式 | **必须是 `_mers.tga`**（100% 实测），不要输出 `_mer.png` |
| 通道重映射 | LabPBR `_s` 的 R=感知平滑度 → MERS 的 B=粗糙度，需 `pow(1-s, 2)`；LabPBR 的 A=自发光 → MERS 的 G；LabPBR 的 G / B 里的 F0 与孔隙率 → MERS 的 R / A |
| 文件配对 | 每个基色纹理必须**同时**产出 `<name>.texture_set.json` 与 `<name>_mers.tga`，缺一不可（官方 1:1） |
| `texture_set.json` | 固定写 `format_version: "1.21.30"` + `color` + `metalness_emissive_roughness_subsurface`，不要写 MER |
| `manifest.json` | **必须加** `capabilities: ["pbr"]`（官方样例包没写，不能照抄）；`min_engine_version` 按目标版本写 |
| `textures_list.json` | **不必生成**（官方包自己都没有）；但纹理量大时生成一份可避免内容日志警告 |
| 法线 / 高度 | 官方极少用（4 / 0），优先级低于 MERS；items 类别禁用 heightmap 的规则仍成立 |
| 打包 | `.mcpack` 里 `manifest.json` 必须在根，别套外层文件夹 |

## 九、结论与仍待人工确认的点

**结论**：10/11 号文档的**主干判断是对的**（三层结构、MERS+TGA、保留名机制、1.21.90 按群系优先、fog 引用方式），但**细节命名有 8 处偏差**，其中最需要改的是：`default_fog_setting.json` 的单复数、`textures_list.json` 被误当必需、「9 类目录」被误当原版实存、`format_version` 表被误读为游戏版本。已按本报告修正 10/11 号文档相应段落。

**仍需确认**：
- 稳定版 1.26.60.5 与这个 preview 1.26.70.23 之间的 schema 差异（本次只有 preview 样本）；
- `cubemaps/` / `shadows/` / `local_lighting/` / `pbr/` 的**第三方写法**是否仍按 10/11 号文档有效 —— 官方包没提供样例，只能依赖 MS Learn 文档，无法用实物验证；
- 官方包里 `*_normal.*` 27 个但只有 4 个 texture_set 引用，剩余用途未查。
