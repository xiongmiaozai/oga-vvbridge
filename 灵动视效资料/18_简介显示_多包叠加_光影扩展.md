# 资源包简介显示、多包叠加要求、光影扩展（除贴图外还能做什么）

> 整理日期：2026-11-16　|　资料来源：Microsoft Learn 官方文档、Bedrock Wiki / 社区文档、Minecraft Wiki 镜像、第三方实测整理

## 一、资源包简介（游戏内显示）能用哪些"模板"

### 1. 直接写在 manifest：`header.name` / `header.description`

```json
{
  "format_version": 2,
  "header": {
    "name": "包名（显示在资源包列表）",
    "description": "简介，显示在包名下方两行，过长会被截断",
    "uuid": "...", "version": [1, 0, 0], "min_engine_version": [1, 21, 120]
  },
  "modules": [ ... ],
  "capabilities": ["pbr"]
}
```

- `description` 是**纯文本字符串**；`name`/`description` 都会显示在资源包选择界面。
- Java 的 `pack.mcmeta` 简介（可能含 `§` 颜色码、富文本组件）**不能直接搬进来**：基岩版简介按纯文本渲染，`§` 色码不生效，需要先剥离、保留多行。这正是本项目转换器 `descText()` → `cleanDescription()` 已实现的逻辑。
- 来源：Microsoft manifest reference + Fumora《Bedrock manifest.json Explained》（第三方整理）；Java 侧"两行/截断/pack.png 封面"描述来自 Minecraft Wiki（社区）。

### 2. 想按语言显示不同简介 → 用 `texts/` 本地化（这才是"模板"的正解）

基岩版允许用语言文件覆盖清单里的包名与简介，实现多语言"模板"：

| 文件 | 作用 |
|---|---|
| `texts/languages.json` | 声明包支持的语言代码数组，如 `["en_US","zh_CN"]` |
| `texts/en_US.lang`、`texts/zh_CN.lang` | 键值对；用 `pack.name=…`、`pack.description=…` 覆盖游戏内显示的包名/简介 |
| `texts/language_names.json` | 仅自定义语言时需要，定义语言在设置菜单里的显示名 |

`.lang` 文件格式要点：
- 键值用 `=` 分隔：`pack.description=第一行\n第二行`。
- 换行用 `\n` 或 `~LINEBREAK~`。
- 注释用 `##`（行内注释的尾随空格不会被裁掉；缩进用 Tab）。
- 参数替换 `%s` / `%1`（原版文本由游戏填值）。
- 每行 CRLF 换行、无重复键、`#` 前用 Tab——这是微软本地化的技术要求。
- 必配 `languages.json`，否则游戏不知道要为这些语言应用本地化。
- **坑**：使用自定义语言时，禁用所属资源包前必须先在设置里切换回其他语言，否则游戏会崩溃。
- 语言文件放在**行为包**也能改清单的 name/description，但只能改这一处。

> 来源：wiki.bedrock.dev《Intro to Text & Localization》、bedrock-docs《本地化》、base dev wiki 教程（均为社区文档）。

### 3. 游戏内封面：`pack_icon.png`

- 放在资源包根目录，**128×128 正方形 PNG**；游戏在资源包选择界面把它当作缩略图/封面显示。
- Java 对应的是根目录 `pack.png`。两者文件名不同，转换时需要改名并生成合规图。
- 本项目转换器已在输出侧统一生成合规封面，并支持上传自定义封面（见 `16_` 号）。

### 小结：简介"三件套"

| 显示项 | 直接写法 | 多语言/模板写法 |
|---|---|---|
| 包名 | `manifest.header.name` | `texts/<lang>.lang` 的 `pack.name` + `languages.json` |
| 简介 | `manifest.header.description` | 同上的 `pack.description` |
| 封面 | 根目录 `pack_icon.png`（128×128） | 无本地化概念，所有语言共用一张 |

## 二、多资源包叠加：如何不报错

### 1. 覆盖顺序（决定"谁生效"）

- 资源包列表里**越靠上的包优先级越高**；同一资源（同名贴图/同名文件）由高优先级包覆盖低优先级包。
- 只有一方提供的资源，无论顺序都会被使用——所以一个只改少数几张图的小包可以压在大底包之上。
- 微软文档同时有"后应用的包覆盖同名文件"的表述，与 Wiki 的"最上方胜出"读起来相反；**实际以自己交换顺序测试为准**（Fumora 明确指出这点）。社区实测普遍按"上方优先"。
- 世界自带的资源包配置可能**覆盖全局资源**（Global Resources）：某世界不生效时，要在该世界的资源包设置里单独启用。
- 来源：Minecraft Wiki、微软资源包教程（社区整理 + 官方）。

### 2. 让叠加"不报错"的硬性要求

按重要程度排序，前 4 项是本项目的实际踩坑点（详见 `17_` 号）：

1. **`texture_set.json` 不跨包合并**。高优先级包会**整体替换**同名 texture set 定义，不做字段级合并；只提供部分层的包会让某样东西显示异常。别指望"A 包给颜色层、B 包给法线层"能拼起来。
2. **全局单例只能有一个**。`pbr/global.json` 是全局单例，两个 PBR 包都带会冲突 → 这就是把转换包和 ENRO 一起用时报"资源包加载错误"的根因之一。解决：叠加用包不要输出 `pbr/global.json`（本项目"与现有 PBR 包叠加使用"选项）。
3. **包内必须干净**：macOS `._` AppleDouble 伪文件（内容不是 PNG 却被当基色塞进 `textures/`）、空格文件名、重复 ZIP 条目、非法 PNG，都会触发"资源包加载错误"。本项目 `clean_pack.py` 与引擎卫生补丁已处理。
4. **texture set 定义本身必须合法**，否则记 content error 且**整组不生效**：缺 `color` 层；`normal` 与 `heightmap` 同时存在；`MER` 与 `MERS` 同时存在；引用的贴图缺失；通道数错误。
5. **能力/版本要对齐**：VV 包需 `capabilities:["pbr"]` 且 `min_engine_version ≥ [1,21,120]`；不含 `pbr` 的包会把图形模式限制到 Fancy 或更低，与 VV 包叠用可能压掉高级效果（例外：`metadata.product_type=addon` 可无视 pbr 启用 VV）。
6. **UUID 不能复用**：包与模块之间、两个包之间都不要用同一个 UUID；依赖的 UUID/版本要精确匹配目标包，否则包不激活。
7. **同类型图片的格式优先级**：`.tga > .png > .jpg > .jpeg`。
8. **Java 目录/元数据差异**：Java 用 `block/` 单数、基岩用 `blocks/` 复数；Java `.mcmeta` 动画不通用，基岩用 `flipbook_textures.json`。

### 3. 排查冲突的标准流程

复制一份世界 → 逐个只激活一个包确认它自身正常 → 每次加一个包复测 → 谁加进去后出错谁就是冲突方 → 交换顺序：贴图变了＝资源覆盖问题；没变化＝通常是行为包/定义冲突。全程看 **content log**（会记录重复/无效定义、无效 texture set）。在测试副本上操作，别在原世界直接增删行为包（可能留下实体/物品占位符）。

> 来源：Fumora《Bedrock Pack Order and Add-on Conflicts》《Bedrock Vibrant Visuals and Ray Tracing Packs》、icedfox / macmyths 安装教程、mcshuo 中文整理（均为第三方实测）。

## 三、灵动视效：除了替换贴图还能做哪些光影

Vibrant Visuals 本质是 RenderDragon 的**延迟渲染 + PBR 光照**体系。资源包除了给方块/实体/物品/粒子换 MERS 材质，还能用 JSON 配置一整套"光照与大气"，且大部分支持**按一天中的时间做关键帧**。

### 1. 可用 JSON 配置的效果（资源包侧）

| 类别 | 能做什么 |
|---|---|
| **PBR / MERS 材质** | 逐贴图定义金属度、自发光、粗糙度、次表面散射；MERS 可用于方块、实体、生物、粒子、物品（MER 仅方块、仅光追包） |
| **光源 light sources** | 点光源、方块光源的颜色/强度、静态彩色光照 |
| **大气 atmospherics** | 天空地平线色/天顶色、瑞利散射、米氏散射（仅日出日落）、太阳/月亮颜色与照度、随群系/维度差异 |
| **体积雾与光轴** | volumetric fog 强度、散射/吸收、light shafts 光束、按群系密度、距离衰减 |
| **色彩分级 color grading** | 饱和度、对比度、gain、gamma、冷暖色调；14 种群系分级 |
| **色调映射 tone mapping** | 映射曲线（部分底层曲线属引擎配置，见下） |
| **关键帧 keyframing** | 大气/光照/体积雾的多数设置可按时间设关键帧：0=正午、0.25=日落、0.5=午夜、0.75=日出、1=次日正午；引擎线性插值 |
| **群系自定义** | 具体见本库 `07_` 号（biome custom） |
| **天气效果** | 天气事件动态改变方向光、雾、云、色彩分级 |

### 2. 由 MERS 材质间接影响、但有引擎级配置的部分

- **水面效果**：焦散、散射、Snell 窗、水下光束——资源包能通过材质/大气间接影响，细项多为引擎配置。
- **反射**：SSR、IBL/cubemap 主要由金属度/粗糙度（MERS）决定；反射类型本身属引擎配置。
- **阴影**：方向光/太阳月亮的像素对齐阴影；阴影距离/分辨率属引擎配置。

### 3. 资源包**改不了**的引擎级配置（避免白费功夫）

`platform_configuration.json`、阴影距离/分辨率、反射类型、最大点光源数、延迟渲染距离、light clustering、luminance、含 shader 代码的 `.bin` 材质文件、`brdf_lut.png`、天气底层配置。这些在引擎/Renderer 配置目录，不在普通资源包可编辑范围。

### 4. 制作工具

**Bedrock Editor** 自带 Vibrant Visuals Settings 图形界面：可视化改大部分 JSON、实时看效果、把配置复制为 JSON 或一键生成资源包，再通过 `mctools.dev` 导出/继续定制。注意编辑器里的设置改动**不自动保存**。

### 5. 前置条件与限制

- 声明 `capabilities:["pbr"]` + `min_engine_version ≥ [1,21,120]`；或 `metadata.product_type=addon`（此时即便无 pbr 也能启用 VV，自定义贴图默认 0% 金属 / 0% 自发光 / 100% 粗糙 / 0% SSS）。
- **设备门槛**：Windows 需 D3D12 feature level 12_1（Intel 显卡驱动 ≥ 31.0.101.3430）；Android 需 Adreno 640+ / Mali Valhall(G68,G77) / PowerVR A 系 / Xclipse 530+ 等；iOS 需 A12 Bionic+/iPhone XS+；Xbox Series X|S、PS5、Switch 2 等支持，部分旧主机默认关闭。Raw text 中若干 GPU 名为未展开模板，具体以官方设备列表为准。
- 服务器可在 `server.properties` 用 `disable-client-vibrant-visuals` 禁用 VV；主机本地分屏会把图形模式限制到 Fancy 或更低。
- **Java 版尚未正式支持**（Mojang 正把渲染迁到专用线程 + Vulkan 后再引入）。

> 来源：Minecraft Wiki（sasgaming 镜像）《Vibrant Visuals》、Microsoft Learn《Vibrant Visuals resource packs》《PBR overview》《Biome customization》、doortogaming《Bedrock Shaders in 2026》（第三方）。

## 与本项目（LabPBR2VV）的关系

- **第一节**已落地（2026-11-16）：转换器在保留 `header.description`（去色码、保留多行）的基础上，新增默认开启的「生成多语言简介模板」开关——输出 `texts/languages.json`（`zh_CN`/`en_US`）+ `texts/zh_CN.lang` + `texts/en_US.lang`，用 `pack.name` / `pack.description` 覆盖游戏内显示，把 Java 原介绍与转换记录按语言展示（未机器翻译，两种语言同为原文、作为可编辑模板）。`.lang` 值里的换行按基岩规则转义为字面 `\n`；只改显示层键，叠加不报错。
- **第二节**与 `17_` 号实证完全互相印证：texture_set 不合并、`pbr/global.json` 单例、卫生清理、pbr/min_engine_version 对齐——正是转换器"叠加模式"要规避的。
- **第三节**说明当前转换器只做"贴图层"（MERS + 法线/高度），不涉及光源/大气/雾/色彩分级等 JSON 配置；这是后续可扩展的方向，但注意这些不是 Java LabPBR 贴图能直接提供的，需要另行设计映射。

### 本次实现记录（2026-11-16）
- 引擎：`LabPBR2VV.html` 新增 `toLangValue()`、UI 开关 `optI18n`（默认开）、`convert()` 输出 `texts/` 三件套；报告新增 `localization` 字段与 `conversion.options.localizedDescription`。
- 验证：静态守卫 +4（36/36）、CDP 多语言断言 +7（desc 18/18）、包校验 A2 组 +7（72/72）；`bash verify/run_all.sh` 全绿。
- 用法：转换时保持「生成多语言简介模板」勾选即自动生成；想改某语言的展示文案，直接编辑包内对应 `.lang` 的 `pack.description=` 一行（换行用 `\n`）。
