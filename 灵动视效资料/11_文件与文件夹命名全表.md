# 灵动视效资源包 · 文件与文件夹命名全表

> 整理日期：2026-11-15
> 目标：把「灵动视效（Vibrant Visuals）资源包」里**每一个文件夹名、文件名、后缀**逐项列出，说明它代表什么、干什么用、以及命名上要注意什么。
> 依据：Microsoft Learn 创作者文档、Minecraft Wiki `Resource_pack` 目录清单、Bedrock Wiki（textures_list / Client Biomes）、基岩文档中文站、bedrock.dev，以及本文件夹 04–07、10 号资料
> 适用版本：Bedrock 1.21.120+（部分 schema 已到 1.21.130 / 1.26.x）
> ⚠️ 校验状态：已用官方样例包 `bedrock-samples-v1.26.70.23-preview-full.zip` 逐项核对。**官方包实际只用了 5 类设置目录**（`cubemaps/` `shadows/` `local_lighting/` `pbr/` 四类为创作者可选扩展，原版包中不存在），`textures_list.json` 也并非必需；细节修正见 `12_官方样例包校验报告.md`。

## 零、先看懂命名的三条总纲

1. **门禁决定一切**：下表中标 `[PBR]` 的目录/文件，**只有 `manifest.json` 里写了 `capabilities: ["pbr"]` 才会被引擎读取**；否则整目录被静默忽略。Wiki 的原始注释就是 `Only in resource packs with "pbr" capability`。
2. **命名分三类**：
   - **保留名（reserved）**：文件名被写死，引擎靠它认「全局默认值」，改名即失效；
   - **自由名 + 唯一 identifier**：除保留名外可任意命名，但同目录下**文件名不能重复、文件内 `identifier` 不能重复**；
   - **约定后缀**：贴图靠 `_mers` / `_normal` 这类后缀与同名基色纹理配对。
3. **大小写与路径**：目录名全小写、复数形式固定（`atmospherics/`、`cubemaps/`、`fogs/` …）；JSON 里引用贴图用**不带扩展名**的路径。

## 一、根目录文件

| 名称 | 类型 | 代表什么 / 功能 | 注意事项 |
|---|---|---|---|
| `manifest.json` | 必需 JSON | 包的身份证；`header`（name/description/uuid/version/`min_engine_version`）、`modules`（`type: "resources"`）、`capabilities` | **VV 的全部开关都在这里**：必须 `capabilities: ["pbr"]` 且 `min_engine_version ≥ [1,21,120]`，缺一项所有 PBR 资产不渲染。`"raytraced"` 也能激活但限定 RTX 设备，官方推荐 `pbr`。两个 uuid 必须各不相同 |
| `pack_icon.png` | 图片 | 设置界面里显示的包图标 | 缺失时显示默认图标；建议 256×256 以内 |
| `bug_pack_icon.png` | 图片 | **包加载失败时**显示的图标 | 容易被漏掉；排查「图标变了」问题时很有用 |
| `biomes_client.json` | JSON | 给「在 `biomes/` 里没有设置」的群系提供回退值，**并且会覆盖所有原版（Vanilla）设置** | 1.21.90 起原版包内置了按群系配置，这个文件反而成了整包覆盖原版效果的手段；与 `biomes/*.client_biome.json` 不是一回事，别混用 |
| `blocks.json` | JSON | 方块纹理短名 → 实际贴图的映射（旧式方块定义） | 常规资源包文件，与 VV 无直接关系，但纹理短名要与 `texture_set.json` 的 `color` 对得上 |
| `sounds.json` / `splashes.json` | JSON | 声音事件登记 / 闪烁标语文本 | 通用文件。`splashes.json` 只在标题界面用到 |
| `sub-pack/`（Wiki 也写 `subpacks/`） | 目录 | **子包**：内部是同样目录结构的一整套资源，游戏内可单独开关 | 多个子包必须在 `manifest.json` 里声明。VV 常用它给低性能设备配一套低分辨率/无 MERS 的降级资源（官方纹理预算要求 VV 内容至少满足 Tier 2） |
| `*.mcpack` / `*.zip` | 打包产物 | 整个根目录压缩后的可导入文件 | 不是包内文件；压缩时**不要把外层文件夹一起打进去**，要让 `manifest.json` 位于压缩包根部 |

## 二、`[PBR]` 九大设置目录总表

这 9 个目录就是「灵动视效专属配置」的全部。Wiki 对它们统一标注了 `Only in resource packs with "pbr" capability`。

| 目录名 | 保留的默认文件名 | 根 schema 对象 | 控制什么 | 实例数量 |
|---|---|---|---|---|
| `atmospherics/` | `atmospherics.json` | `minecraft:atmosphere_settings` | 大气散射（瑞利/米氏）、天空色、地平线混合 | 多实例，按群系 |
| `color_grading/` | `color_grading.json` | `minecraft:color_grading_settings` | 饱和度、对比度、增益/偏移、色调映射、温度分级 | 多实例，按群系 |
| `lighting/` | `global.json` | `minecraft:lighting_settings` | 日月定向光、环境光、天空光、自发光、末地闪光 | 多实例，按群系 |
| `water/` | `water.json` | `minecraft:water_settings` | 水体粒子浓度、波浪、焦散、水下吸收 | 多实例，按群系（按**几何位置**插值） |
| `fogs/` | `default_fog_setting.json` | 迷雾定义 | 雾、体积散射、Henyey–Greenstein `g` | 多实例 |
| `cubemaps/` | `cubemap.json`（见下文） | `minecraft:cubemap_settings` | 天空盒 / IBL 立方体贴图的光照贡献 | 多实例（1.21.130+） |
| `shadows/` | `global.json` | `minecraft:shadow_settings` | 阴影风格（`blocky_shadows` / `soft_shadows`）、`texel_size` | **整包一份** |
| `local_lighting/` | `local_lighting.json` | `minecraft:local_light_settings` | 指定方块（火把、灯笼…）的点光颜色与类型 | **整包一份** |
| `pbr/` | `global.json` | `minecraft:pbr_fallback_settings` | **没有 `texture_set` 的对象**的 MERS 回退值 | **整包一份** |

> **含义区分**：前四类（atmospherics / color_grading / lighting / water）是「世界怎么打光」，随玩家所在群系平滑过渡；后五类基本是整包统一设定。两层之间的桥是 `pbr/global.json`。

## 三、九大目录逐项展开（命名细节）

### 3.1 `atmospherics/`

| 文件 | 说明 |
|---|---|
| `atmospherics/atmospherics.json` | **保留名**。全局默认大气，identifier 自动分配给所有没有专属配置的群系 |
| `atmospherics/end.json`、`nether.json` … | 自定义实例。文件名任意但**必须唯一**，文件内 `description.identifier` 也必须唯一且带命名空间 |
| `atmospherics/location.json` | Wiki 目录清单里的记法：「Contains atmospherics configurations for specified locations」。属早期 / 按 location 的表述，现代写法是上面的多实例 + `client_biome` 引用 |

- `format_version`：字符串，最新 `1.26.20`；1.21.40 起由整数数组改为字符串。
- 1.21.40 路径从旧 `atmospheres/` 正式迁到 `atmospherics/atmospherics.json` —— **旧教程里的 `atmospheres/` 是过时写法**。
- 必填 `description.identifier`。

### 3.2 `color_grading/`

| 文件 | 说明 |
|---|---|
| `color_grading/color_grading.json` | **保留名**，全局默认 |
| `color_grading/*.json` | 自定义实例（官方教程写 `color_grading/*.json`），需唯一文件名 + 唯一 identifier |
| `color_grading/location.json` | Wiki 记法：按位置的配置 |

- `format_version`：`1.21.90`（1.21.90.25 起要访问温度分级 `temperature grading` 必须写 `1.21.90`）。
- **色调映射算子（tone mapping operator）不能按群系单独改**，同包内必须保持一致，否则群系间无法过渡。

### 3.3 `lighting/`

| 文件 | 说明 |
|---|---|
| `lighting/global.json` | **保留名**。全局光源：太阳、月亮、末地闪光、自发光、环境光、天空光 |
| `lighting/end.json` … | 自定义实例 |
| `lighting/location.json` | Wiki 记法：指定位置的光源配置 |

- `format_version`：官方教程示例 `1.21.70`（用了 `directional_lights.orbital`），最新 schema 已到 `1.26.0`；1.21.80 起 `directional_lights` 取代旧 `orbital` 写法。
- ⚠️ **最容易踩的坑**：1.21.90 起原版 Vanilla 包加入了按群系光照且**优先级更高**，`lighting/global.json` **不再能覆盖**原版群系效果。必须新建专属 JSON 并在 `biomes/*.client_biome.json` 里用 `minecraft:lighting_identifier` 显式引用。
- `orbital_offset_degrees` 不能按群系混合，同包需一致。

### 3.4 `water/`

| 文件 | 说明 |
|---|---|
| `water/water.json` | **保留名**，全局默认 |
| `water/ocean.json`、`deep_ocean.json` … | 自定义实例；官方 07 号资料里的示例就是这么命名的 |
| `water/location.json` | Wiki 记法：指定位置的水配置 |

- `format_version`：`1.21.40` 起字符串；`minecraft:water_settings`。
- identifier 记法有分歧：Wiki 写顶层 `identifier`（`minecraft:default_water` 即全局默认），1.21.40 官方 schema 写 `description.identifier`。**按你目标版本的 schema 写**，别混。
- 三个浓度参数：`cdom`(0–15)、`chlorophyll`(0–10)、`suspended_sediment`(0–300)，默认都是 0。
- **焦散自定义贴图**：必须放在 `textures/` 目录下、在 `textures_list.json` 里声明，且所有动画帧**纵向排列、每帧同为正方形分辨率**。
- 焦散参数、波浪开关布尔值不能按群系混合。
- 水按**几何位置**插值（不是观察者位置），所以站岸边能同时看到不同群系的水色。

### 3.5 `fogs/`

| 文件 | 说明 |
|---|---|
| `fogs/default_fog_setting.json` | **保留名**，默认雾配置 |
| `fogs/location.json` | Wiki 记法：指定位置的雾配置 |

- 1.21.90.26 起新增 `henyey_greenstein_g`（`air` / `water` 各一个值）。
- ⚠️ 引用方式容易搞错：Wiki 的 Client Biome 文档里是通用组件 **`minecraft:fog_appearance` 的 `fog_identifier` 字段**指向 `RP/fogs` 里的定义；它**不属于** VV 专属的那组 `*_identifier` 组件。10 号文档里写的 `minecraft:fog_identifier` 是笔误，已在本文修正。

### 3.6 `cubemaps/`（1.21.130 新增）

| 文件 | 说明 |
|---|---|
| `cubemaps/cubemap.json` | Wiki 目录清单的写法 |
| `cubemaps/mycubemap.json` | 1.21.130 官方示例用**任意文件名**，例如 `cubemaps/mycubemap.json` |

- **文件名其实不固定**：真正决定作用范围的是 `description.identifier`。写成 `minecraft:default_cubemap` 时默认被所有群系使用；否则要在 `biomes/<群系>.client_biome.json` 里用 `minecraft:cubemap_identifier` 指向它。
- `format_version` 必须 `1.21.130`；根 `minecraft:cubemap_settings`；`lighting` 为必填对象（内部字段可省）。
- `lighting` 字段：`ambient_light_illuminance`（可关键帧，默认 5.625）、`sky_light_contribution`(0–1)、`directional_light_contribution`(0–1)、`affected_by_atmospheric_scattering`(默认 false)、`affected_by_volumetric_scattering`(默认 true)。
- 自定义 cubemap 只影响主世界天空，**末地天空盒不受影响**。

### 3.7 `shadows/`

| 文件 | 说明 |
|---|---|
| `shadows/global.json` | **保留名，整包唯一一份**，全局生效 |

```json
{
  "format_version": "1.21.80",
  "minecraft:shadow_settings": {
    "shadow_style": "blocky_shadows",
    "texel_size": 16
  }
}
```

- `format_version` 必须 `1.21.80`。
- `shadow_style`：`blocky_shadows` / `soft_shadows`。⚠️ **官方文档与 Wiki 对默认值说法相反**：MS Learn 说未自定义时默认 `soft_shadows`，Wiki 说默认 `blocky_shadows` —— 建议**显式写出**你要的值，别依赖默认。
- `texel_size` 默认 16，应与你包内方块贴图分辨率一致（16×16 → 16，32×32 → 32），否则阴影无法对齐像素网格。

### 3.8 `local_lighting/`

| 文件 | 说明 |
|---|---|
| `local_lighting/local_lighting.json` | **保留名，整包一份**。给火把、灯笼、自定义发光方块指定静态光/点光颜色 |

- `format_version` `1.21.120`。
- ⚠️ **改名历史**：1.21.120 之前叫 `point_lights/global.json`（`minecraft:point_light_settings`），旧教程会写成这个路径。看到 `point_lights/` 就知道是过期写法。
- 键用带命名空间的方块 ID，例如 `"minecraft:torch": { "light_color": "#EFE39D", "light_type": "point_light" }`。

### 3.9 `pbr/`

| 文件 | 说明 |
|---|---|
| `pbr/global.json` | **保留名，整包一份**。没有 `texture_set` 的方块/实体/粒子/物品，统一从这里取 MERS 默认值 |

```json
{
  "format_version": "1.21.40",
  "minecraft:pbr_fallback_settings": {
    "blocks":    { "global_metalness_emissive_roughness_subsurface": [0, 0, 255, 0] },
    "actors":    { "global_metalness_emissive_roughness_subsurface": [0, 0, 255, 0] },
    "particles": { "global_metalness_emissive_roughness_subsurface": [0, 0, 255, 0] },
    "items":     { "global_metalness_emissive_roughness_subsurface": [0, 0, 255, 0] }
  }
}
```

- `format_version` `1.21.40`；四个分类键固定为 `blocks` / `actors` / `particles` / `items`。
- `[0,0,255,0]` = 非金属、不发光、完全粗糙、无次表面散射，是常见保守值。**缺失贴图时的表现由这里决定，不是自动取原版** —— 忘了写会让缺贴图物体发亮或过暗。
- 这个文件是「材质层」和「设置层」之间唯一的桥。

## 四、`biomes/` 与引用组件命名

| 名称 | 说明 |
|---|---|
| `biomes/<biome>.client_biome.json` | 客户端生物群系定义。文件名通常取群系 ID，如 `the_end.client_biome.json`、`hell.client_biome.json`、`ocean.client_biome.json`、`river.client_biome.json` |
| 后缀 `.client_biome.json` | **双段后缀**，不是 `.json`。写错成 `biomes/the_end.json` 不会被识别 |
| `format_version` | 1.21.70（旧示例）/ 1.21.130（用 cubemap 时） |
| 根对象 | `minecraft:client_biome` → `description.identifier` + `components` |

**VV 专属的 5 个引用组件**（注意：没有 `fog_identifier`）：

| 组件名 | 字段 | 指向目录 | 最低版本 |
|---|---|---|---|
| `minecraft:atmosphere_identifier` | `atmosphere_identifier` | `atmospherics/` | 1.21.90 |
| `minecraft:color_grading_identifier` | `color_grading_identifier` | `color_grading/` | 1.21.90 |
| `minecraft:lighting_identifier` | `lighting_identifier` | `lighting/` | 1.21.90 |
| `minecraft:water_identifier` | `water_identifier` | `water/` | 1.21.90 |
| `minecraft:cubemap_identifier` | `cubemap_identifier` | `cubemaps/` | **1.21.130** |

雾走的是另一条：通用组件 `minecraft:fog_appearance` → `fog_identifier` → `RP/fogs`。

> **规则**：四个保留文件名（`atmospherics.json` / `color_grading.json` / `global.json` / `water.json`）里的 identifier 会**自动**分配给所有群系，除非某个 `client_biome.json` 显式改掉。1.21.90 起原版包的按群系配置优先于这些全局文件。

## 五、`textures/` 目录与贴图命名

### 5.1 子目录

| 目录 | 内容 | PBR 支持 |
|---|---|---|
| `textures/blocks/` | 方块纹理 | ✅ |
| `textures/entity/` | 实体 / 生物纹理 | ✅ |
| `textures/items/` | 物品纹理 | ✅（**不能用 heightmap**） |
| `textures/particle/` | 粒子纹理 | ✅ |
| `textures/models/` | 模型贴图 | 常规 |
| `textures/ui/` | UI 图（`graphic.png` / `.jpg` / `file.json`） | 常规，不参与 PBR |

> 官方那张 `rp-file-structure3.png` 示意图**漏画了 `textures/items/`**，但实际支持。别被图误导。

### 5.2 一个纹理的完整文件组（以铁块为例）

```
textures/blocks/
├── iron_block.png                   ← 基色（color），无后缀，必需
├── iron_block.texture_set.json      ← 纹理集定义，与贴图同目录
├── iron_block_mer.png               ← MER 三通道（RTX / 旧式）
├── iron_block_mers.tga              ← MERS 四通道（VV 推荐，与 MER 二选一）
├── iron_block_normal.tga            ← 法线（与 heightmap 二选一）
└── iron_block_heightmap.tga         ← 高度图（与 normal 二选一）
```

> ⚠️ **这是「可选层菜单」，不是必须凑齐的 6 件套**：`_mer` 与 `_mers`、`_normal` 与 `_heightmap` 都是 schema 级互斥，同一个 `texture_set.json` 里不能同时声明（否则 `CONTENT_ERROR`，整个纹理集不生效）。官方样例包里 `iron_block` 实际只有 **3 个文件**：`iron_block.png`、`iron_block.texture_set.json`、`iron_block_mers.tga`；`_mer.png` 出自 MS Learn 的旧 RTX 教程（`1.16.100` + MER），`_heightmap` 全包 0 个。逐文件的通道 / 格式 / TGA 字节序实测见 [13_纹理文件通道与格式详解.md](./13_纹理文件通道与格式详解.md) 第一、九节。

| 后缀 / 命名 | 通道 | 代表什么 |
|---|---|---|
| （无后缀） | RGB / RGBA | `color` 基色，通常烘焙了光照；传统管线只读这一层 |
| `_mer` | RGB | R=金属度、G=自发光、B=粗糙度（RTX 用；VV 也能用但拿不到 SSS） |
| `_mers` | **RGBA** | R=金属度、G=自发光、B=粗糙度、**A=次表面散射**（VV 专属） |
| `_normal` | RGB | 切线空间法线（4 通道时 A 被忽略） |
| `_heightmap` / `_height` | 单通道 | 高度图，引擎据此算法线 |
| `.texture_set.json` | — | 双段后缀；文件基名必须与被定义纹理**同名** |

**格式优先级**：同名时 `.tga` > `.png` > `.jpg` > `.jpeg`。
⚠️ **MERS 必须用 TGA**：Alpha=0 与 255 都有语义，Photoshop 等工具优化 PNG 时会丢掉 Alpha=0 区域的 RGB 数据。

### 5.3 纹理注册表文件（都在 `textures/` 根）

| 文件 | 格式 | 功能 | 注意事项 |
|---|---|---|---|
| `textures_list.json` | **字符串数组** | 缓存清单；引擎据此快速定位贴图 | 路径**不含扩展名**（`.png`、`.tga`、`.texture_set.json` 都要去掉）。例：`"textures/blocks/iron_block"`。漏登记会出现内容日志警告，纹理多时可能串图或不加载。**新增 `_mers.tga` / `_normal.tga` 后记得补登记**；自定义焦散贴图也必须在 `textures/` 下并登记 |
| `terrain_texture.json` | JSON | 方块纹理短名 → 路径（`atlas.terrain`） | 短名要与 `texture_set.json` 的 `color` 值一致 |
| `item_texture.json` | JSON | 物品纹理短名 → 路径（`atlas.items`） | Wiki 目录清单未列出，但 mcbe-dev 教程明确使用 |
| `flipbook_textures.json` | JSON | 翻页动画纹理（如水面、岩浆） | 与 VV 焦散动画不同，别混 |

`textures_list.json` 示例：

```json
[
  "textures/blocks/iron_block",
  "textures/blocks/iron_block_mers",
  "textures/blocks/iron_block_normal",
  "textures/items/iron_ingot"
]
```

### 5.4 `*.texture_set.json` 的字段命名

```json
{
  "format_version": "1.21.30",
  "minecraft:texture_set": {
    "color": "iron_block",
    "metalness_emissive_roughness_subsurface": "iron_block_mers",
    "normal": "iron_block_normal"
  }
}
```

| 字段名 | 通道 | 可否写数值/HEX | 约束 |
|---|---|---|---|
| `color` | RGBA | 可（4 值数组 / HEX） | **唯一必需层**；传统管线唯一读取的层 |
| `metalness_emissive_roughness` | RGB | 可（3 值） | 与 MERS **互斥**；RTX 用 |
| `metalness_emissive_roughness_subsurface` | RGBA | 可（4 值） | 与 MER **互斥**；**仅 VV 支持**，`format_version ≥ "1.21.30"` |
| `normal` | RGB | 否 | 与 `heightmap` **互斥** |
| `heightmap` | 单通道 | 可（单值） | 与 `normal` **互斥**；**不能用于物品类纹理** |

- `format_version`：MER 时代用 `"1.16.100"`，MERS 用 `"1.21.30"`。
- 数值写法：`"#FBA34C"`、`[180, 140, 190, 255]`、`[130,135,140]`，范围 0–255。
- ⚠️ **uniform 值做 MERS 的纹理变体不受支持** —— 要做变体必须给图片型 MERS 文件。
- ⚠️ 层引用的贴图**必须在同一个资源包内**，且通常在同目录；高优先级包里的同名贴图不会顶替引用。
- 会触发 `CONTENT_ERROR` 的命名/组合错误：缺 `color`、同时写 `normal`+`heightmap`、同时写 MER+MERS、物品用 `heightmap`、通道数不符、引用贴图无法解析。

## 六、常规资源包目录（不是 VV 专属，但会同时存在）

做完整包时会看到这些，它们**不因 `pbr` capability 而改变**，列全以免误以为是 VV 文件：

| 目录 / 文件 | 内容 |
|---|---|
| `animation_controllers/entity_animation_controllers.json` | 实体动画控制器 |
| `animations/entity.animation.json` | 实体动画 |
| `attachables/entity.json` | 手持/穿戴物挂接定义 |
| `block_culling/block_culling.json` | 方块剔除规则 |
| `entity/entity.entity.json` | 客户端实体定义 |
| `items/item.json` | 物品客户端定义 |
| `materials/entity.material` | 材质（旧式渲染管线，注意与 PBR `texture_set` 区分） |
| `models/entity.geo.json` | 几何模型 |
| `particles/particle.json` | 粒子定义 |
| `render_controllers/`（`entity_render_controllers.json`、`default.render_controllers.json`） | 渲染控制器 |
| `sounds/`（`music_definitions.json`、`sound_definitions.json`、`sound.ogg/.wav/.fsb/.mp3`） | 声音；`.mp3` 支持不完整 |
| `texts/`（`languages.json`、`language_names.json`、`zh_CN.lang`、字体 PNG） | 本地化；`manifest.json` 里的 `guide.pbr_pack.name` 这类键就在这里翻译 |
| `textures/ui/` | UI 图片与 `file.json` |

> ⚠️ 命名上有两个易混点：`materials/entity.material` 是**旧渲染管线**的材质文件，与 PBR 的 `*.texture_set.json` 完全是两套东西；`sounds/`、`texts/` 与 VV 无关。

## 八、命名相关的高频踩坑清单

- [ ] 目录写成 `atmospheres/`（旧）→ 应为 **`atmospherics/`**；官方示意图本身就是旧的。
- [ ] `point_lights/global.json`（旧）→ 1.21.120 起为 **`local_lighting/local_lighting.json`**。
- [ ] 群系文件写成 `biomes/the_end.json` → 必须 **`*.client_biome.json`**。
- [ ] 保留名被改（如 `lighting/default.json`）→ 全局默认值失效，且不报错，最难查。
- [ ] 同目录下两个 JSON 用了相同 `identifier` → 后面的覆盖前面的。
- [ ] `format_version` 写成整数数组 `[1,21,40]` → 1.21.40 起必须是**字符串** `"1.21.40"`。
- [ ] `description.identifier` 没带命名空间（写成 `end_lighting`）→ 引用不上，应写 `my_pack:end_lighting`。
- [ ] `textures_list.json` 里写了 `"textures/blocks/stone.png"` → 应去掉扩展名。
- [ ] MERS 存成 PNG → Alpha 数据可能被工具优化掉，**用 TGA**。
- [ ] 新增 `_mers` / `_normal` 后忘了在 `textures_list.json` 登记 → 内容日志警告 / 贴图串位。
- [ ] 以为 `lighting/global.json` 能改末地光照 → 1.21.90 起必须建专属 JSON + `client_biome` 引用。
- [ ] 把 `minecraft:fog_identifier` 当成 VV 组件 → 实际是 `minecraft:fog_appearance` 的 `fog_identifier` 字段。
- [ ] 只改了 `manifest.json` 却没设 `min_engine_version` → PBR 资产仍不渲染。
- [ ] 压缩 `.mcpack` 时多套了一层文件夹 → 导入后找不到 `manifest.json`。
